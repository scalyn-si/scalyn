01 / EXECUTIVE SUMMARY

Real discovery.
Inferred intelligence.

The current system is a hybrid of live web retrieval and generated analysis. It can discover real indexed pages without a social account. It does not establish that every name is a person, every URL is reachable, or every prospect intends to buy.

OBSERVED / NETWORK DATA

Where the real part comes from

In the upgraded “Phase 4/5” scraper, requests fetches DuckDuckGo HTML and Bing search pages; ddgs provides another search route. DOM selectors yield titles, snippets, and destination URLs.

LOCAL RETRIEVAL CONTRACTtitle → search-result page titleurl → decoded destination linksnippet → search-index excerpthandle_or_name → title/domain heuristic

The URL originates in a search index. The company name is cleaned from the title or domain; it is not checked against a business registry.

INFERRED / GENERATED ANALYSIS

Where interpretation begins

Business models, personas, regions, match scores, competitor comparisons, and outreach hooks can come from keyword rules and templates. An optional Gemini branch may replace some extraction and scoring.

A field called verified_url stores a candidate URL; the name alone does not prove identity or availability. A failed page fetch can still produce a “broken website” signal and leave the prospect in the output.

No current local scraper fallback manufactures a list of social users. If search fails, it can return zero results. Existing Excel rows have no automatic historical provenance cleanup.

HISTORICAL ACCOUNT / NOT VERIFIED IN THIS CHECKOUT

The “Phase 1/2” fallback reality

The supplied project history describes early fallback outputs such as google.com/search?q=..., u/startup_builder_99, and @growth_operator. A search wrapper is a query to run, not a discovered profile; an archetype handle is synthetic until tied to an observed source.

Missing external executables or API access can motivate a demo fallback, but missing tooling does not require fabricated leads. The right behavior is to identify demo data or report an unavailable source.

These exact historical examples are not present as active lead-generation branches in the reviewed Python files. No version history was available to establish when they ran. The phase labels are supplied narrative, not independently verified release tags.

02 / UNDER THE HOOD

Two tools. A shared name.

tools/agent_reach_tool.py is scalyn.si’s own adapter and scraper. Panniantong/Agent-Reach is a separate open-source tool. Their capabilities and command interfaces should be evaluated independently.

THIS PROJECT

A local HTTP search adapter

shutil.which() checks whether an agent-reach executable exists on PATH. It was absent in the reviewed environment. The app therefore uses its own DuckDuckGo → DDGS → Bing routes.

If installed, the adapter attempts agent-reach search QUERY --platform PLATFORM --limit N --json, parses a list or a results object, and falls back when that produces no accepted output.

Compatibility gap: this assumed command is not the current documented upstream channel/action interface. Installing the upstream tool alone does not establish that this integration works.

UPSTREAM AGENT-REACH

A dispatcher to platform tools

Upstream dispatches each channel/action through an ordered backend list. Its current web channel uses Exa search and Jina/Exa reading; social channels can use OpenCLI with a dedicated browser session.

The current channel sources document login-backed X actions, Reddit browser actions alongside public-web routes, and LinkedIn job actions. They do not describe universal anonymous profile scraping.

Primary sources: web channel, X channel, Reddit channel, LinkedIn channel. Reviewed 09 Nov 2026; upstream main can change.

Public endpoints & RSS

Some services expose public HTML, feeds, or unauthenticated reads. Access varies by route and network. This local scraper does not implement social RSS ingestion, a Reddit JSON client, or guest-token flows.

Headers ≠ a browser

The local Requests session supplies a user-agent, accept headers, and cookies. Headers do not reproduce a browser’s TLS/JA3 fingerprint. DDGS may use different transports depending on its installed version; this project does not control a custom JA3 profile.

Public ≠ unlimited

Indexes omit pages, snippets age, and services impose dynamic limits. HTTP 202 challenges, 403/429 responses, timeouts, and selector changes can stop discovery. No universal requests-per-minute allowance is established here.

Why preserve OR?

("Founder" OR "CEO") asks for either role. Removing OR can turn alternatives into a request for every role on one page. The repaired adapter preserves quoted phrases, Boolean alternatives, and site: restrictions. Search engines may still interpret syntax differently.

05 / LOCAL VS. AI

The engine runs on Python.
AI is an optional layer.

“Agent” describes an automated workflow here. The default path can fetch pages, classify by rules, draft queries, rank candidates, fill templates, and save Excel without invoking a language model or using a social media account.

requestsBeautifulSoupre / urllib.parsePydanticopenpyxlDDGSThreadingHTTPServer
01 / RETRIEVAL

Deterministic network engineering. Requests fetches HTML; BeautifulSoup selects tags; URL parsing decodes redirects. DDGS searches remotely. No LLM is needed, but internet access and available search providers are required.

02 / REASONING

Rules in the default path. Industry keywords choose a taxonomy branch; lists supply personas and competitor candidates. Relevance starts at 5 and receives keyword boosts or penalties. This is text matching and templated analysis, not a trained semantic model.

03 / OUTPUT

Structured file operations. Dataclasses and Pydantic organize values; conditional strings generate pitches; JSON/CSV serializers and openpyxl persist handoffs. Model-generated content must still be validated before entering these layers.

OPTIONAL / LLM

Two implemented hooks. Site extraction and relevance scoring attempt Gemini when GEMINI_API_KEY is present in the process environment. Both use a hardcoded gemini-1.5-flash call through google.generativeai. Failures fall back to rules. SDK/model availability needs validation; the settings model name does not control these calls.

Zero LLM usage is possible

The taxonomy can map “inventory” to supply-chain software and attach likely operations personas. The planner chooses query templates; the score gate uses token overlap; the pitch generator inserts names and the client’s UVP.

This explains how the system works without expensive AI calls. Its flexibility is bounded by the handwritten categories and templates. “Deep semantic reasoning” in a docstring is not evidence of an AI model.

Configuration is not integration

The requirements file lists google-antigravity, but it does not explicitly declare the google.generativeai SDK imported by the hooks. No active dotenv-loading call was found in these paths; a .env file alone is not established configuration.

Despite broader docstrings, there is no implemented OpenAI, Ollama, or Groq extraction/scoring adapter in the reviewed path. The current pitch generator uses templates throughout.

PROPOSED EXTENSION / NOT WIRED INTO THIS APP

Put a small local model at the interpretation boundary

A local quantized model served through Ollama could classify a bounded text excerpt and return a validated business profile. Python would continue handling the HTTP, HTML, URL filtering, deduplication, and file writes. Model quality, RAM/VRAM, quantization, and context size determine latency and reliability.

07 / LIMITS & EVIDENCE
Know what the system
can actually prove.
These implementation details are essential to interpreting a dossier. Expand each note to see where an observation ends and an assumption begins.

  
Do friction signals prove a business needs the product?
No. The five checks are indicators: HTTP URLs or missing viewport metadata; keyword matches for manual booking; copyright-year patterns; unreachable pages; and missing direct contact links. They are not validated commercial intent.
  • The SSL check inspects the original URL string, not a full TLS configuration audit; an HTTP URL may redirect to HTTPS.
  • A missing viewport tag does not prove the rendered page fails on mobile.
  • “WhatsApp to order” is a text match, not observation of a complete booking workflow.
  • The copyright regex uses a static pre-2024 cutoff and can miss or misread dates; it is not rolling with the current year.
  • A timeout, login wall, or anti-bot response may be reported as a broken website even when the site works for people.
  • A contact link may live on another page or be JavaScript-rendered. The audit reads a limited landing-page text excerpt.

  
Are competitors and buyer personas researched facts?
Not by default. Site ingestion chooses from fixed taxonomy branches, each with preset personas, competitor candidates, and some canned UVPs. The fallback category is B2B SaaS. These suggestions may be plausible but are not evidence that a business competes with every listed company.
The dossier’s competitor analysis then applies generic strengths and complaints without fetching supporting competitor pages. The optional extraction model can also invent unsupported details. Keep observed text separate from inferred conclusions.

  
Is this a recursive crawler or a full browser?
No. The primary ingestor fetches one submitted page and follows HTTP redirects. When readable text is short, it attempts up to two selected JavaScript bundles and extracts string fragments. It does not execute JavaScript, render a DOM, crawl all internal pages, or run a general headless browser.
The reviewed repair preserves the script-presence flag before stripping tags, so the bundle branch can execute. It also calls raise_for_status() and rejects empty/unreachable input pages. A challenge page that returns HTTP 200 can still be misinterpreted.

  
Does the score gate guarantee clean, platform-correct prospects?
No. Wikipedia, Britannica, TripAdvisor and other noisy sources are filtered by blacklist rules. Some checks use substring matching instead of strict hostname matching, which can reject innocent URLs or fail to enforce boundaries. LinkedIn and Reddit result filtering is also substring-based; X has a site query restriction but no equivalent explicit result-host filter in every engine parser.
A mention of a competitor can raise relevance while pointing to a vendor, article, or irrelevant community. A generic role and the client’s target city may be written into prospect fields. The gate needs evaluation against labeled outcomes before treating its threshold as validated precision.

  
Does Excel deduplication guarantee unique entities?
The implementation lowercases and trims URLs and stored names, then skips a candidate if its URL or name already appears. The comparison spans the workbook rather than being scoped to a client. It does not resolve tracking parameters, trailing slash variants, redirects, or company aliases.
Rows may store a display value like “name (organization)” while the incoming comparison uses only name_or_handle, weakening the name check. URL comparison remains separate. Concurrent runs also have no demonstrated transaction or file-lock protection; Excel is a local workbook, not a transactional database.

  
Are the sales hooks fully dynamic and evidence-backed?
They use conditional string templates. Competitor mentions, industry phrases, and the top signal choose a branch; names and UVPs fill it. A competitor mention can trigger a pricing-hurdle claim even without a complaint. The generator checks tech_stack_gap, while the detector emits technical_gap, so that case can fall through to generic text.
If no signals are observed, the researcher creates a medium-severity signal from query intent. The pitch is therefore a draft that may contain inferred claims. It is not automatically sent to anyone.

  
What was actually verified in this session?
The running API successfully extracted a profile from a public Python website, returned HTTP 422 for an unreachable test domain, and served the dashboard with HTTP 200. The local repair’s eight Python regression checks and five dashboard action checks passed. Two older query-planner tests failed against unchanged planner code.
A live search probe encountered a DuckDuckGo HTTP 202 challenge, DDGS failures, and unrelated Bing results. This is evidence that network requests ran, not evidence of dependable lead discovery across every platform. Existing workbook rows were not independently audited.
The documentation itself is an offline explanation, not a fresh health monitor. Its diagrams and query tools use illustrative data.

  
!
Before treating a row as a qualified lead: inspect its source page, confirm the entity and actual region, distinguish observed from inferred signals, and review draft claims. A real indexed URL is the beginning of verification.
